# Reuse before research

Find relevant work before repeating it, then verify the facts the present decision depends on. The user's scope and requested sources lead. An existing note is a starting point, not proof that a changing fact is current.

## Find what matters

Check relevant project files, notes, installed skills or prior handovers where available. Search earlier chats only if they are accessible and useful. Scale discovery to the task: do not inventory every source for a small question. Keep track of the source, date and whether it is an observation, an earlier decision or a proposed method.

If the user explicitly requests fresh research, browse or check the named sources even when an old note appears sufficient. If a source or tool is unavailable, use other appropriate evidence, identify the gap and avoid implying that the missing source was checked.

## Reuse and refresh

- Reuse a relevant method or stable historical fact with its provenance. Check whether it fits the current question and constraints.
- Refresh changeable or decision-critical facts, such as prices, software versions, rules, people and service status, against suitable current sources. A past decision is evidence of what was decided then, not necessarily of current conditions.
- Explain material changes and unresolved discrepancies. When current information cannot be checked, label the old value as dated and avoid presenting it as current.

## Preserve useful knowledge within scope

When the user requests a durable record, or existing project instructions authorize maintaining one, update the appropriate existing note and link its sources and date. Prefer an existing home over a duplicate. Propose a reusable improvement when useful; edit or create a skill, archive files, or write to an external service only within the task's authorization. Never save passwords, keys or private personal data in public notes or skills.

## Example

A prior note says a service costs a particular amount, but the user asks for a current comparison. Reuse its comparison criteria and link to the note as historical context. Check the present price at an authoritative source, state the date and plan or region, and update the conclusion. If the current page is inaccessible, say the price is unverified rather than repeating the old amount as current. Save a new note only if the task or existing workflow calls for it.
